# my-sdk

> **Note:** this README was written by an AI (Claude) to save time. Double-check
> it against the code before relying on it.

TypeScript SDK for interacting with the My API used by Epitech
(`https://my.epitech.eu/api/`).

## Architecture

```text
src/
├── api/                # Generic HTTP/API infrastructure
│   └── client.ts
├── auth/               # Authentication state and auth flows
│   └── authenticator.ts
├── interfaces/         # API contracts, one folder per domain
│   ├── api/            # ApiResult, ApiError, PaginationMeta
│   ├── common/         # Types shared by several responses
│   ├── applications/
│   ├── attendance/
│   ├── auth/
│   ├── calendar/
│   ├── campus/
│   ├── cursus/
│   ├── e-learning/
│   ├── evaluations/
│   ├── events/
│   ├── exams/
│   ├── gamification/
│   ├── notifications/
│   ├── projects/
│   ├── settings/
│   ├── units/
│   └── user/
├── services/           # One class per domain, extending ApiClient
├── utils/              # Generic helpers (query string, validators...)
├── index.ts            # Public package exports
└── main.ts             # Local smoke tests against the live API
```

Every service extends `ApiClient`, keeps no state besides the access token, and
returns an `ApiResult<T>`.

## Usage

```ts
import { Student, Events } from "./index.js";

const student = new Student(process.env.EPITECH_TOKEN);
const profile = await student.getStudentProfile();

if (profile.success) {
    console.log(profile.data.login);
}

const events = new Events(process.env.EPITECH_TOKEN);
const week = await events.getEvents({
    startDate: "2026-09-14",
    endDate: "2026-09-20",
    registered: "me",
});
```

## `ApiResult<T>`

Every API helper returns a detailed `ApiResult<T>` containing:

- `success`: whether the request produced an acceptable SDK result.
- `status`: HTTP status code, or `0` when no HTTP response was received.
- `expectedStatus`: whether the status code matched the statuses expected by the caller.
- `expectedStructure`: runtime validation information generated by typia.
- `raw`: the raw parsed response body (`unknown` so the result also supports non-JSON responses).
- `data`: the typed response data when the request and validation succeed, otherwise `null`.
- `error`: an error message when `success` is false.
- `delay`: request duration in milliseconds.
- `address`: best-effort DNS-resolved IP address for the response hostname.
- `url`: final request URL.
- `method`: HTTP method used.
- `responseHeaders`: response headers as a plain object.
- `contentType`: value of the response `Content-Type` header, when present.

`expectedStructure` is intentionally separate from `success`. A server can
return a successful HTTP status while changing or breaking the response
payload shape. In that situation, `expectedStructure.valid` is `false` and
`errors` contains the detailed typia validation errors.

Typia generates the runtime validator from the TypeScript type at compile time,
so API services only need to provide the expected generic type. No
`isUserDetailsResponse()`-style validator is required for each interface.

> Note: Typia is a compile-time transformer. This project uses `ttsc` instead
> of the stock `tsc` compiler so that `typia.validate<T>()` is transformed
> correctly. See the official Typia setup documentation for the current
> toolchain requirements.

### Known limitations

- `POST users/photos/urls`: the request body was not part of the capture, the
  `{ logins }` payload is an assumption.
- Staff-only endpoints (`403` for students) are not implemented.
- Requests with an empty response body (e.g. marking an e-learning chapter as
  viewed) are not implemented.
- Interfaces reflect a single account's data: a field that was always `null`
  in the capture is typed `unknown`, and a field missing from some samples is
  optional. Adjust them when other accounts or cursus reveal more shapes.

## Utilities

- `withQuery(endpoint, params)` (`utils/query.ts`) appends query parameters,
  skips `null`/`undefined` values and serializes arrays as `key[]=value`
  (e.g. `cursus[]=PGE`).
- `validateUnknown` (`utils/validators.ts`) accepts any body, for endpoints
  without a documented schema.

## Development

```bash
npm install
npm run typecheck
npm run build
```

`src/main.ts` is a smoke-test script that calls every service against the live
API and reports, for each call, whether the status and the response structure
match the interfaces. It reads the token from `.env`:

```text
EPITECH_TOKEN=<your access token>
```
